# Product Detail Page Auto Skill v3.0

## 발동 조건
사용자가 '상세페이지 제작', '상품정보 입력', '전체 자동 진행', '다음 섹션', 'Figma 생성', '기존 상세페이지 수정' 또는 이와 동등한 의사를 밝히면 이 스킬을 적용한다. 현재 프로젝트의 상품 사진·정보·레퍼런스를 우선 사용한다. 사용자가 승인 없이 진행하라고 하면 원칙적으로 중간 승인을 생략하되, 사실 오류·권한 선택·게시 등 실질적인 결정이 필요한 경우만 확인한다.

## 최상위 원칙
1. 사용자가 제공한 실제 상품 이미지가 최우선이다. 로고, 패턴, 색상, 실루엣, 원단, 포장 또는 라벨을 임의로 바꾸지 않는다. 상품 이미지가 없다면 무단으로 다른 상품 사진을 대체하지 않고 명확한 이미지 placeholder를 둔다.
2. 사실은 `confirmed_by_user`, `verified_source`, `inferred`, `missing`으로 구분한다. 수치, 소재, 기능, 원산지, 인증, 가격, 후기, 배송정책을 추측하여 확정하지 않는다.
3. 모든 디자인 산출물 너비는 860px로 한다. Figma 단일 마스터 프레임은 860px 너비에 11개 내외 섹션을 세로로 배치하며, 콘텐츠가 충분할 때 전체 높이는 12,000px 이상을 권장한다. 각 섹션의 독립 이미지 내보내기는 너비 860px, 높이 최소 1,200px를 기본으로 하며 짧은 정보 섹션도 내보내기 전 padding으로 규격을 충족한다. 콘텐츠가 부족할 땐 무의미한 문구를 늘리지 않고 `missing_content` 기록 및 총 높이 미달을 허용한다.
4. 출처 없는 기능성 주장과 최상급 표현, 의료 효능, 경쟁사 이미지를 복제하는 행위를 금지한다. 원본 5개 참고 지침은 `references/`에 그대로 보관하며 충돌 시 이 최상위 원칙을 적용한다.
5. 순차 단계 산출물은 JSON으로 생성·검사하고, 단계별 상태와 오류를 기록한다. `issues`가 있다고 실행을 무조건 중단하지 않는다. 상품 정체성을 결정할 필수 정보가 없으면 확인하고, 나머지는 placeholder로 진행한다.
6. 이미 생성한 Figma 결과는 가능하면 재사용한다. 변경된 섹션만 재생성하며 이전 섹션과 무관한 내용을 손상시키지 않는다.

## 실행 흐름
### STEP 1 입력 정규화
`references/01_상품정보입력_지침서.md`를 읽고 `schemas/product.schema.json` 규격에 따라 입력을 정리한다. 필수: 상품명, 브랜드명, 상품카테고리, 기본설명. 키워드 3~7개를 상품 데이터에 근거해 추출한다. 오탈자 보정과 브랜드 공식 표기의 출처를 구분한다. 사진이 있다면 실제 상품 사진 목록을 별도 자산 매니페스트로 관리한다.

### STEP 2 레퍼런스 분석
`references/02_레퍼런스수집_지침서.md`: 현재 접근 가능한 주요 판매 채널에서 동일·유사 상품 3~6개, 가급적 2개 이상의 채널을 조사한다. 상품명/채널/실제 URL/확인 일자/섹션 패턴/카피 톤/우선 정보/차별점/확신도를 수집한다. 페이지를 직접 보지 못한 경우 섹션 구성 등을 확인한 것처럼 단정하지 않는다. 디자인·문구를 그대로 복제하지 않는다. 검색 실패 시 확보한 근거와 미확인 필드를 표시한다.

### STEP 3 사실 검증·카피
`references/03_웹리서치_지침서.md`: 공식 브랜드, 제조사, 공인 인증기관, 법령 자료를 우선한다. 상품별 사실표에 `field`, `value`, `evidence_type`, `url`, `confidence`, `checked_at` 기록. 카피 후보 3~5개는 확인된 사실과 사용자 설명에서만 작성하고 미확인 기능성은 플래그. 식품(원산지·원재료·알레르기·보관·기한·신뢰), 패션(소재·색상·사이즈·원산지·관리), 뷰티(전성분·사용법·검증된 표시) 등 카테고리 체크리스트 적용.

### STEP 4 레이아웃 명세
`references/04_레이아웃기획_지침서.md`를 바탕으로 `schemas/layout.schema.json` 형식의 섹션 구조를 생성한다. 기본 카테고리: 히어로 → USP → 사용 상황 → 상세 근거/핏/원물 → 디테일 → 컬러/규격 → 사용/스타일링 → 상품고시 → 관리/보관 → 배송·FAQ. 필요한 섹션만 추가/삭제·통합한다. USP는 전체 높이 상단 30% 이내. 각 섹션에 order, id, title, height_px, copy, content_elements, image_guide, source_fact_ids, status를 반드시 명시한다. 이전 단계 근거 없는 사실 문구를 최종 카피에서 제거한다. 원본 4단계의 900px은 860px로 바꿔 적용한다.

### STEP 5 Figma 편집형 생성
`references/05_Figma생성_지침서.md`: Figma 연결 및 권한 확인 → 사용자의 승인받은 team/organization plan key 사용 → 새 Figma 디자인 파일 또는 지정 파일 → 폰트 `loadFontAsync` → 메인 프레임 860px 생성 → `order` 순서로 하위 섹션 프레임 → 텍스트 노드·이미지·명시적 placeholder 생성 → 저장 상태 재조회 및 실측 검증. 기존에 확인된 기본 팀은 `5changhoon`이지만 권한이 변경될 수 있으니 팀 목록/편집 권한 재확인. plan key가 다수이고 특정 팀을 지정하지 않았다면 선택 필요. 실행은 비동기 완료까지 대기하고 종료 전 프레임 존재를 검사한다. 사용 가능한 한국어 폰트를 먼저 로드하며 Pretendard가 제공되지 않으면 대체 글꼴을 기록한다. `width 860`, `height`, 섹션수, 노드수, 오버플로 위험, 링크 접근을 확인한다.

### STEP 6 검수 및 출력 (v3.0 추가)
`QA_CHECKLIST.md`를 따른다. 검사 실패는 `errors`/`warnings`로 나누며 확인이 필요한 상품 정보와 디자인 기술오류를 구분. 결과로 Figma 링크, 섹션 구조, 누락 목록, 출처 목록, 카피 최종안, 변경 로그 제공. 사용자가 이미지 출력·ZIP을 요청했다면 각 섹션을 독립 PNG/JPG로 내보내고 860px 폭 및 최소 1200px 높이를 확인한 다음 ZIP 묶기. 이미지 자산이 없는 상태에서는 빈 이미지를 완성본으로 주장하지 않는다.

## 재진입 명령
- '전체 자동 진행': 입력 확인 이후 모든 실행 가능한 단계를 중간 승인 없이 수행한다.
- '다음 섹션': 현재 완료된 섹션 다음만 진행한다.
- 'N섹션 수정': 지정 섹션의 이미지·문구·노드만 수정하고 나머지는 보존한다.
- 'Figma 다시 생성': 저장된 레이아웃을 이용해 새 Figma 초안 생성한다.
- '정보만 검수': Figma 생성 없이 상품 사실/법적 위험/누락 항목 검사한다.
- 'ZIP 출력': 섹션별 이미지 출력 가능한 상태에서 ZIP으로 묶는다.

## 실행 전후 체크포인트
입력 식별 → 정확한 상품 여부 → 출처 접근 가능성 → 카피 검증 → Figma 쓰기 권한 → 실제 노드 재조회 → 최종 검수. 실패 시 실패한 단계와 사유를 밝히고 이전 성공 산출물을 유지한다. 원본 지침과 결정이 달라진 지점은 `CHANGELOG.md`를 참조한다.
